# Battle Royale — single-file Unity prototype

`BRGame.cs` (1,224 lines) — a complete, drop-in battle-royale shooter for Unity.
Nothing to import: **no prefabs, no models, no packages, no external assets**. The camera,
sun, map, bots, loot, HUD and touch controls are all generated by code.

## Setup (2 minutes)

1. Unity 2021.3 LTS or newer, **Built-in Render Pipeline** (URP also works — the material
   factory falls back to `Universal Render Pipeline/Lit`).
2. New empty scene → create an empty GameObject (`GameObject → Create Empty`) → rename it
   `BRGame`.
3. Add the component: `Add Component → BRGame`.
4. Press **Play**. Done.

`BRActor` is in the same file, so there is no second script to attach and no
`Missing script` reference to wire up.

> The file must be named **`BRGame.cs`** — Unity requires the MonoBehaviour's class name to
> match the filename. `BRActor` being a second (non-file-named) class in the same file is
> legal C# and legal Unity.

## Controls

| Action | Desktop | Mobile |
|---|---|---|
| Move | `WASD` | virtual stick (left half of screen) |
| Look | hold **right mouse** + move | drag anywhere on right half |
| Fire | **left mouse** (hold) | `FIRE` button |
| Reload | `R` | `RELOAD` button |
| Heal (+50 HP) | `H` | `HEAL` button |
| Jump | `Space` | `JUMP` button |

UI is laid out in a virtual **960 × 540** space and scaled to the real resolution, so it
looks the same on a phone and in the editor Game view.

## Gameplay

- Circle map, 160 m, ~22 solid buildings + 22 low cover blocks. Buildings are solid
  blocks (`// this version has no interiors` in the original) — cover only.
- 15 bots. They pick the nearest target within 48 m, advance to ~18 m, then strafe, and fire
  with 62 % accuracy for 7–13 damage. They also run for the safe zone when the circle
  catches them.
- Shrinking safe zone: 7 HP/s outside, ramping to 18 HP/s **after** the match timer expires.
- Loot: 24 ammo/medkit crates (yellow = +60 ammo, green = +1 medkit), auto-pickup within 1.7 m.
- Headshots do 65 damage, body shots 26. Kills refund 20 reserve ammo.
- Win = last one alive. Lose = eliminated (final position shown). `PLAY AGAIN` restarts
  without reloading the scene.

## What was verified

No .NET SDK / Mono / Unity is available in this sandbox (`dotnet`, `mcs`, `csc` all absent,
and `api.nuget.org` / `dot.net` are blocked), **so this was not compiled**. What *was* run:

- **Syntax**: parsed with `tree-sitter-c-sharp` → **0 errors, 0 missing nodes**; braces and
  parens balanced (104/104, 524/524).
- **Structure**: 2 classes, 36 methods in `BRGame`; every locally-called method resolves to a
  declaration in the same class (32/32), none unresolved.
- **Unity API surface**: every `Mathf.`, `Vector2/3.`, `Quaternion.`, `Physics.`, `Input.`,
  `Screen.`, `Random.`, `Time.`, `GUI.`, `GUIStyle.`, `RenderSettings.`, `CharacterController.`,
  `LineRenderer.`, `Camera.` member used was checked against the Unity scripting API names.
- **No HTML entities** remain in the file.

### Known limits (by design, not bugs)

- Bots use obstacle **steering**, not pathfinding — they can get stuck against a long wall.
- Buildings are solid; there is no interior navigation.
- No audio, no VFX beyond the tracer line, no animation (capsules).
- `Physics` layers are not used: every raycast hits everything, which is fine at this scale but
  should move to a `LayerMask` before adding more geometry.
- Not tested on a device — the touch layout was geometry-checked against the 960 × 540
  virtual space but never finger-tested.

## If you want it to be a real game next

1. Replace `BRActor` capsules with a rigged model + an `Animator` (keep `CharacterController`).
2. Swap `OnGUI` for a `Canvas` UI — IMGUI is fine for a prototype, costly per frame on mobile.
3. Add `NavMesh` + `NavMeshAgent` for bots instead of steering.
4. Move `FirstHit()` raycasts to a `LayerMask` and cache `RaycastAll` arrays
   (`Physics.RaycastNonAlloc`) to stop per-shot allocations.
